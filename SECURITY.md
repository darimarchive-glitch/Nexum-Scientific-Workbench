## Como relatar uma vulnerabilidade

Prefira um canal privado. Use **GitHub Security Advisories / private vulnerability reporting** do repositório quando estiver disponível. Se esse recurso não estiver acessível, use um meio de contato publicado no perfil do mantenedor no GitHub.

Não publique detalhes de exploração, payloads funcionais, credenciais, dados privados ou uma prova de conceito perigosa em uma issue pública antes de haver oportunidade de análise.

Inclua versão, plataforma, componente afetado, pré-condições e impacto observado. Para arquivos maliciosos, descreva o formato e forneça a amostra somente por um canal privado apropriado.

## Escopo relevante

Relatos de segurança podem incluir, entre outros:

- execução inesperada de código ao abrir projetos ou dados;
- escape do isolamento usado para extensões;
- escrita/leitura de arquivos fora dos caminhos pretendidos;
- processamento inseguro de arquivos `.nexum7` ou formatos importados;
- carregamento inseguro de bibliotecas ou DLLs;
- vazamento de dados ou credenciais;
- vulnerabilidades de dependências que afetem o pacote distribuído.

Falhas exclusivamente numéricas ou científicas devem ser relatadas pelo fluxo normal de suporte, a menos que também criem impacto de segurança.
